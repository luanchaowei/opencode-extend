# 功能变更文档同步

## 触发条件

当对 opencode-extend 项目源码进行以下任何变更后，必须执行文档同步：

- 新增功能或页面
- 修改现有功能行为
- 删除功能或移除 UI 元素
- 修改配置项（.env 变量、命令行参数）
- 新增、修改或删除 API 接口（路由、请求参数、响应格式、权限级别）
- 修改数据库表结构（新增/修改/删除表、字段、索引、外键、清理规则）

## 文档清单

| 文档 | 路径 | 覆盖范围 |
|------|------|---------|
| 安装指南 | `doc/install-guide.md` | 环境要求、部署说明、安装、配置、启动方法 |
| 使用指南 | `doc/user-guide.md` | 面向终端用户，描述页面上可见的功能 |
| 运维指南 | `doc/admin-guide.md` | 面向管理员，描述管理面板各 Tab 的功能 |
| API 接口文档 | `doc/api-reference.md` | 全部 HTTP API 接口的路径、参数、响应、权限 |
| 数据库表结构 | `doc/database-schema.md` | stats.db 的表结构、字段、索引、外键、写入时机、清理规则 |
| 工具脚本指南 | `doc/tools-guide.md` | 命令行工具脚本用法 |
| 编译打包指南 | `doc/build-guide.md` | 编译为可执行文件 |
| README | `README.md` | 项目总览、文档目录、项目结构 |

## 同步规则

### 1. 仅描述用户可见的功能

- 用户指南和运维指南只体现用户在页面上能直接看到和操作的功能
- 不描述内部实现机制（如心跳上报逻辑、isOwnProject 判定、数据库表结构等）
- 不描述被裁剪掉的功能（代码中注册但 UI 已隐藏或 disabled 的快捷键、按钮等）

### 2. 变更对照表

每次功能变更后，对照以下清单检查文档是否需要更新：

| 变更类型 | 需检查的文档 |
|---------|-------------|
| 前端 UI 变更（新增/修改/删除页面元素） | `user-guide.md` |
| 管理面板变更（统计/监控/设置/用户管理） | `admin-guide.md` |
| API 接口变更（新增/修改/删除路由、参数、响应） | `api-reference.md` |
| 数据库表结构变更（新增/修改/删除表、字段、索引） | `database-schema.md` |
| 脚本工具变更（session-cleanup / query-stats） | `tools-guide.md` |
| 配置项变更（.env 新增/删除/重命名） | `install-guide.md` + `admin-guide.md`（如可在设置页配置） + `api-reference.md`（如影响 /device/info 或 /api/config/runtime 响应） |
| 命令行参数变更 | `build-guide.md` |
| 编译流程变更 | `build-guide.md` |
| 部署/启动流程变更 | `install-guide.md` |
| 认证机制变更（角色/权限/中间件） | `api-reference.md` + `admin-guide.md` + `user-guide.md` |
| 数据清理规则变更（保留天数/清理对象） | `database-schema.md` |

### 3. 快捷键处理

- 仅在快捷键命令实际可用（UI 按钮存在且未 disabled）时才写入文档
- 如果快捷键对应的按钮被 `display:none` 隐藏，或命令被 `disabled`，则不写入文档
- 代码中注册但功能不可用的快捷键，应同时删除命令注册代码和文档条目

### 4. 配置项同步

- `.env` 中的配置项变更后，需同步更新 `install-guide.md` 的配置示例和 `admin-guide.md` 的系统设置表
- 如配置项出现在 `/device/info` 或 `/api/config/runtime` 的响应中，需同步更新 `api-reference.md`
- 命令行参数变更后，需同步更新 `build-guide.md` 的参数表

### 5. API 接口同步

- `server.js`（或 `vite.js`）中新增/修改/删除路由时，必须同步更新 `api-reference.md`
- 检查项：路径、HTTP 方法、查询参数、请求体字段、响应格式、权限级别、错误码
- 新增配置项如通过 `/device/info` 或 `/api/config/runtime` 暴露，需补充到对应接口的响应示例中
- `handleAPI` 函数中的路由处理和 `Bun.serve` 中的页面路由（`/login`、`/admin.html`）都需覆盖

### 6. 数据库表结构同步

- `stats-db.js` 中新增/修改/删除表、字段、索引、外键时，必须同步更新 `database-schema.md`
- 检查项：表名、字段名、字段类型、主键、外键、索引、默认值、字段说明
- 新增字段需说明写入时机和取值含义
- 修改数据清理规则（保留天数、清理对象、触发频率）时需同步更新清理规则章节
- 新增数据写入事件时需同步更新「数据写入时机」表
- `ALTER TABLE` 动态添加的字段也需在文档中标注为「预留字段」或说明实际用途

## 执行流程

1. **识别变更范围**：根据本次代码变更，确定受影响的文档文件
2. **读取相关源码**：确认变更后的实际行为（读取组件、API 路由、配置代码）
3. **读取对应文档**：找到需要更新的章节
4. **逐项更新**：按源码实际行为修正文档内容
5. **验证一致性**：确认文档描述与源码行为完全一致

## 验证清单

完成文档更新后，逐项确认：

- [ ] 用户指南和运维指南中描述的每个功能在源码中都存在且可用
- [ ] API 接口文档中每个端点的路径、方法、参数、响应与 server.js 代码一致
- [ ] API 接口文档中权限级别标注正确（公开/已登录/管理员/超级管理员）
- [ ] 数据库表结构文档中每张表的字段、类型、主键、外键、索引与 stats-db.js 建表语句一致
- [ ] 数据库表结构文档中「数据写入时机」表覆盖所有写入事件
- [ ] 配置项在 install-guide、admin-guide、api-reference 中保持一致
- [ ] 被裁剪的功能已从所有相关文档中移除
- [ ] 被裁剪的功能对应的代码也已删除（不仅是文档移除）
